## The claim

After twelve years away from Java, I'm coming back the way I learned to program: by building Swing apps from scratch — a nostalgia project that also gets me fluent in modern Java again.

## For whom

Future me, and anyone who learned on desktop Java and wonders whether that craft still has a place beside Spring, services, and the browser.

## The story

I learned programming through Java and Swing. Windows, listeners, layout managers, the stubborn joy of a JFrame that finally did what you meant. Then I spent about twelve years building on other platforms.

Recently I landed back in a Java-heavy environment. The stack is modern; the muscle memory is not. Rather than only reading docs and cloning service templates, I want a project that makes Java feel like *mine* again.

So I'm starting a small Swing practice: apps from scratch, almost like a love letter to the toolkit that taught me. Not because Swing is the future of product UI — because building something you can see and click is still one of the fastest ways to relearn a language's texture: types, packages, build tools, threading rules, and taste.

## Evidence

- Twelve years away from day-to-day Java, returning now in a Java shop.
- Swing was the original teacher: concrete UI, immediate feedback, no "deploy and hope."
- Modern Java has moved (records, pattern matching, newer JDKs, better tooling) — a from-scratch desktop app is a forced tour through what's changed without drowning in framework ceremony on day one.

## What to take away

- If you're rusty in a language you once loved, pick a small, visible project — not only the framework your job uses.
- Nostalgia is allowed to be useful: the point is fluency and joy, not shipping Swing to production.
- This post is the opener; later notes can walk through the first window, packaging, and modern JDK choices as I build.
